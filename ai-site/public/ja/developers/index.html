端点 / Endpoints

完整路径和响应 schema 在 OpenAPI 里。下面是常用的一组。静态 JSON 带 ETag 和 Cache-Control: public, max-age=300。If-None-Match 返回 304。响应头 X-API-Version: 1。已发布 JSON 正文不另包一层。

The OpenAPI document lists every path and response schema. Static JSON sends ETag and Cache-Control: public, max-age=300. If-None-Match returns 304. Header X-API-Version: 1. Published JSON bodies are not wrapped.

方法路径说明 / What
GET/v1/health进程活着即 200。rate_limit 为 degraded 时限流绑定还没配上，请求仍然放行。Liveness. A missing rate-limit binding does not fail the check.
GET/v1/games/index.json游戏目录。Directory. /v1/games/{id}.json 是单条。
GET/v1/catalog-aliases.json目录别名 → id。不是角色别名。Catalog nicknames, not character nicknames.
GET/v1/feed.json /v1/digest.json /v1/radar.json已发布标题、分游戏摘要、新作雷达。空数组是合法结果。Headlines, per-game digest, new-game radar. An empty array is valid.
GET/v1/watchlist.json /v1/calendar.json观察名单和日程。meta.fixture: true 是示例。Watchlist and calendar.
GET/v1/guides/{game}/banners.json卡池。名称、UP、时间只来自文件。Banners. Do not invent UP names or times.
GET/v1/guides/{game}/codes.json兑换码。本接口不代领。expired 和 expiry_not_stated 不要当成可用。Codes. This API does not redeem them.
GET/v1/guides/{game}/characters/{id}.json角色卡。非 stub 带 https sources 和 as_of。Character card.
GET/v1/personal无状态个人摘要。查询 games、chars（game:id）或分享码 code=gi1.…。不保存名单。Atom：/v1/personal.atom。Stateless personal digest. Nothing is stored.
GET/v1/planner从已发布 banners、calendar、codes 派生的卡池时间线。不保存规划。只有卡池注记写了「首个 N 次征集」才算差额。可选 game、resources=game:数量。Derived timeline. A shortfall exists only for that stated summon count.
GET/v1/compare?ids=同一游戏 2 到 4 张卡的派生对照。空字段是 null，不补。页面把空字段显示为「暂无出处」。Derived comparison. Empty fields stay null.
GET / POST/v1/claims.json /v1/claims投稿镜像。POST 不需要密钥，沿用原有 KV 限额（每 IP 每小时 10 条，每天 100 条）。列出的行在人工复核前不可信。Claims stay keyless. Listed rows are untrusted.
POST/mcp只读 Streamable HTTP MCP。发现文档 /.well-known/mcp.json。

限额与可选密钥 / Limits and an optional key

不带密钥就能读。/v1 和 /mcp 按调用方限流：匿名每 IP 每 60 秒 120 次；带有效密钥每密钥每 60 秒 1200 次。计数按 Cloudflare 节点，不是全球总和。超限是 HTTP 429，带 Retry-After: 60，正文是

Reads work with no key. /v1 and /mcp are limited per caller: 120 requests per 60 seconds per IP when anonymous, 1200 per 60 seconds per key when a valid key is sent. Counters are per Cloudflare location, not a global total. Over the limit is HTTP 429 with Retry-After: 60 and this body:

{ "ok": false, "error": "rate_limited", "message": "…", "api_version": "1", "status": 429, "tier": "anonymous", "limit": 120, "retry_after": 60 }

密钥放在 Worker secret GAME_INTEL_API_KEYS（逗号分隔）。仓库里没有真实密钥。没配置这个 secret 时，不要带密钥，否则是 401 invalid_api_key。绑定还没发布时，Worker 放行请求，不返回 500。GET /v1/health 的 rate_limit 会写成 degraded。

Keys live in the Worker secret GAME_INTEL_API_KEYS (comma-separated). No real key is in the repo. Until that secret is set, omit the key; a presented key is HTTP 401 invalid_api_key. If the rate-limit bindings are not deployed yet, requests are allowed and do not 500. GET /v1/health then reports rate_limit: "degraded".

请求头用 X-API-Key: YOUR_KEY 或 Authorization: Bearer YOUR_KEY。这不是 CLAIMS_API_KEY。POST /v1/claims 忽略这两个密钥，也走原来的 KV 限额，错误正文仍是 {ok:false,error,scope,limit}。

POST /v1/claims ignores both secrets and keeps its existing KV limiter. Its error body is unchanged.

其他闸门错误统一为 {ok:false, error, message, api_version, status}。MCP 协议错误仍是 JSON-RPC。/mcp 的 HTTP 429 用上面的 JSON。

Other gate errors use {ok:false, error, message, api_version, status}. MCP protocol errors stay JSON-RPC. HTTP 429 on /mcp uses the gate JSON.

MCP

先读 /.well-known/mcp.json，再向 /mcp 发 JSON-RPC POST。工具只读已发布 JSON，包括八款深耕的 list_banners、list_codes 和 personal_digest。描述是中英双语。

Read /.well-known/mcp.json, then POST JSON-RPC to /mcp. Tools are read-only, including list_banners, list_codes, and personal_digest for the eight deep games. Descriptions are bilingual.

通用 Streamable HTTP / Generic client

curl -sS https://game-intel-ai.dyk1454683243.workers.dev/mcp \
  -H 'content-type: application/json' \
  -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"curl","version":"0"}}}'

接着 notifications/initialized，再 tools/list 和 tools/call。现代协议 2026-07-28 还要带上与 body 一致的 MCP-Protocol-Version、Mcp-Method、Mcp-Name。Then send notifications/initialized, tools/list, and tools/call. Protocol 2026-07-28 also requires those headers to match the body.

出处 / Sources

  • 两条链接冲突时：官方（Steam 新闻、发行商、商店页）优先于评测站（Prydwen、Inven、GameKee 测评、巴哈、TapTap），再优先于论坛。When two links disagree: official, then review sites, then forums.
  • JSON 里没有的判断，说「未见可靠出处」，不要补。If the JSON does not support a claim, say so. Do not fill the gap.
  • 引用时带上该行的 url 或 sources，以及 as_of。不要改写成没有出处的数字、价格或概率。Quote the stored URL and as_of. Do not turn a row into a number, price, or rate that was not published.
  • stub: true 是身份或不完整卡，不是结论。A stub is an identity or an incomplete card, not a conclusion.
  • POST /v1/claims 的行是投稿，不是已复核事实。Claim rows are submissions, not reviewed facts.
